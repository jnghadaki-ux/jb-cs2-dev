# Decisions

| # | Date | Decision | Why | Rejected alternatives |
|---|---|---|---|---|
| D1 | 2026-10-10 | One CounterStrikeSharp plugin assembly (`SwbsJailbreak.dll`) with internal modules, instead of one plugin per original SourceMod plugin. | Each SMPlugins `.smx` talked to the others through natives/forwards. Cross-plugin calls in CSS need a shared contract assembly in `shared/` and capability lookups that silently fail if load order or versions differ. One assembly removes that whole class of runtime failures and is one folder to install. | The user's earlier attempt (12 separate CSS projects + shared contracts) — kept as reference only. |
| D2 | 2026-10-10 | Original natives/forwards become C# interfaces in `Core/Api.cs` (`Jb.Warden`, `Jb.Cells`, …) with null-object defaults, plus C# events in `JbEvents`. | Preserves the original module boundaries (warden, cells, LR, days, effects…) so each can be disabled in config without breaking the others ("optional features must not disable the core"). | Direct module-to-module references. |
| D3 | 2026-10-10 | **Superseded by D13.** Multi-target `net8.0` (CSS API 1.0.368) and `net10.0` (CSS API 1.0.376). | The owner requires .NET 8 compatibility; CSS ≥1.0.370 is .NET 10 only (verified from NuGet packages). Both builds come from the same source. | Single `net10.0` target (breaks owner's .NET 8 servers); single `net8.0` target compiled against 1.0.368 only (loses the ray-trace API that warden markers need). |
| D4 | 2026-10-10 | Use CSS's native `Listeners.OnPlayerTakeDamagePre` through one `DamageService` dispatcher. | Exists in both API versions; no gamedata signature to break on CS2 updates; one ordered pipeline replaces many SDKHooks OnTakeDamage hooks. | Hooking `CBaseEntity_TakeDamageOld` (signature changed between versions; extra crash risk). |
| D5 | 2026-10-10 | Weapon pickup restrictions hook `CCSPlayer_ItemServices_CanAcquire` only while a rule is active. | Technique used by working CS2 jailbreaks (eGo); keeps the hook off the hot path otherwise. | Permanent hook; stripping after pickup. |
| D6 | 2026-10-10 | Centre-screen HTML is owned by one compositor (`Hud`) and menus render through it. | CS2 shows one centre HTML message at a time; independent writers flicker and overwrite each other (e.g. warden HUD vs LR timer vs menu). | Each module calling `PrintToCenterHtml`; CSS `CenterHtmlMenu` (5 items, fights other writers). |
| D7 | 2026-10-10 | Menus accept `!1`–`!9` (CSS's built-in `css_1..9` key commands, by registering our instance in `MenuManager`) **and** W/S + E + R navigation. | CS2 has no SourceMod radio menus; number keys are weapon slots. Chat numbers always work; WASD is faster. | Chat-only menus. |
| D8 | 2026-10-10 | Admin permissions use CSS's admin system (`admins.json`, groups, `admin_overrides.json`) with a capability → flag map in config. | The SMPlugins `Admins` library was MySQL-backed and tied to the Swoobles website. CSS's system is the standard on CS2 and is configurable without code. | Re-implementing a custom admin database. |
| D9 | 2026-10-10 | Persistence (CT bans, points, mutes, playtime) uses JSON files under `configs/plugins/SwbsJailbreak/data/`. | No native DLLs (SQLite) or external database needed to test; atomic writes off the game thread. A MySQL backend can be added later behind the same `Storage` API. | Porting the SMPlugins MySQL schema (requires the Swoobles database layout); SQLite (native library loading risk inside CSS's plugin loader). |
| D10 | 2026-10-10 | No text/ASCII stand-ins for in-world effects. Beacons, rings, lasers are real `beam` entities; explosions are particles; sounds are sound events. | Owner requirement; text "beacons" (as in the owner's earlier SimpleAdmin plugin) do not render anything in the world. | Centre-text "<<< BEACON >>>". |
| D11 | 2026-10-10 | Speed and gravity changes go through `Movement`, re-applied every tick. | CS2 resets `m_flVelocityModifier` (hit slowdown recovery) and gravity scale; several systems (effects, days, admin commands) need to stack. | Setting the field once (reverts). |
| D12 | 2026-10-10 | Usage-limited orchestration: research/implementation agents run in small waves (≤3 at a time) in isolated git worktrees, one area per agent, merged by the lead. | The first session hit the account usage limit with 11 parallel readers; waves keep progress steady and each area independently buildable. | Large parallel fan-outs. |
| D13 | 2026-10-10 | **.NET 8 only**: `net8.0` against CounterStrikeSharp.API 1.0.368; the net10 build and all `NET10_0_OR_GREATER` code were removed. | Owner directive: their servers run CSS on .NET 8 and work on a .NET 10 build "will not work and will waste usage". | Keeping the multi-target build (D3). |
| D14 | 2026-10-10 | Aimed features use the `player_ping` event (engine crosshair point + pinged entity) and `bullet_impact`, via `Core/Aim`. | Only real engine aim data available on CSS 1.0.368; no gamedata signatures needed. | Trace via native signatures (unverifiable offline, breaks on CS2 updates); fabricated points (forbidden). |
| D15 | 2026-10-10 | Credits: Gdaki = creator (all work before upload, incl. SimpleAdmin); "enhanced with Claude Code" for later work; "inspired by HlStriker, SWBS development/lead admins". | Owner instruction. | — |
| D16 | 2026-10-12 | Provenance: the owner states this mod is also based on a confirmed working CounterStrikeSharp version of the same mod made previously by Gdaki. Recorded in the README credits as the owner's statement. | Owner instruction. The supplied project `Jailbreak-CS2-CounterStrikeSharp_5` (identical to the file supplied at project start) states in its README that it was never compiled against a real CounterStrikeSharp install, its author string is "Jailbreak Ecosystem", and none of its code is in this plugin (checked 2026-10-12: 0 identical code lines, no namespace references). So the claim cannot be shown from the files supplied and is not presented as fact. | If a confirmed working version is supplied with evidence of it running, compare and port from it and document what was reused. |
